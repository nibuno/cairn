nibuno.dev / AWS

cairn.nibuno.dev を公開する仕組み

Cloudflareは親ドメインを管理し、Route 53はCairnの住所を答えます。実際の画面はAWS上のアプリケーションが返します。

いまの状態 アプリとCDKはローカルで検証済みです。AWSリソースはまだ作成していません。

「住所を調べる」と「画面を開く」は別の通信

CloudflareやRoute 53の中を、Web画面のデータが通過するわけではありません。最初に住所を問い合わせ、その回答を使ってブラウザがALBへ直接接続します。

1. 住所を調べる

DNS問い合わせ
01 ブラウザ cairn.nibuno.dev はどこ？
→
02 Cloudflare CairnはRoute 53に聞いてください
→
03 Route 53 ALBの場所を回答
→
04 ALBの住所 接続先が決まる

2. 画面を開く

HTTPS通信
01 ブラウザ HTTPSで接続
→
02 ALB 証明書を確認し、処理を振り分ける
→
03 Cognito 未ログインなら認証し、ALBへ戻す
→
04 ECS ログイン後にCairnの画面を返す

DNSは案内係

名前から接続先を調べます。アプリケーションの記録データは扱いません。

ALBはアプリの入口

HTTPSを受け、正常に動いているECSタスクへリクエストを渡します。

各サービスの担当

サービス Cairnでの担当 管理するもの
Cloudflare nibuno.dev の親DNS cairn をRoute 53へ渡すNSレコード4件
Route 53 cairn.nibuno.dev のDNS ALBを指すAliasレコードと証明書検証レコード
ACM HTTPS証明書 cairn.nibuno.dev が本物であることの証明
ALB 公開入口 HTTPS受付、Cognito認証、ECSへの振り分け
Cognito 利用者のログイン メールアドレス、パスワード、Hosted UI
ECS Fargate Cairn本体の実行 コンテナ、CPU、メモリ、稼働数
